# Monetization Plan (Final Phase)

## Positioning
ProtectedShare is a privacy-first product. Trust is core to growth and retention, so monetization must not weaken perceived security.

## Decision
1. **Primary path (recommended):** Patreon / GitHub Sponsors first.
2. **Secondary path (later):** Google AdSense only on non-sensitive marketing pages (main landing page and static info pages).
3. **Never place ads on:** `/notes`, `/notes/[id]`, `/secrets`, `/secrets/[id]`, `/notepad`, `/workspace`, or any page with sensitive user activity.

## Why this approach
- Ad scripts can reduce trust in a security/privacy tool.
- Support-first monetization aligns better with zero-knowledge branding.
- Ads can still be tested later without affecting core product UX.

## AdSense guardrails (if enabled later)
1. Keep ad code isolated to landing/marketing pages only.
2. Update Privacy Policy and Cookie disclosures.
3. Add consent handling where legally required (GDPR/EEA and similar regions).
4. Do not add invasive trackers in app flows.

## Execution order
1. Launch product with no ads.
2. Add support CTA (Patreon / Sponsors) in footer and about/help pages.
3. Evaluate support revenue and traffic quality.
4. If needed, run a controlled AdSense test on landing page only.
5. Keep or remove ads based on trust, retention, and conversion impact.
